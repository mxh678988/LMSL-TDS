## 2. 差距与机会（竞品雷达对照）

1. **调度可视化蓝海**：LM Studio / Ollama / GPU-Hot 都只做"指标展示"，无人做"淘汰序推演 + 预取预测 + 生克解释"。紫梅控制台已具备此组合，领先窗口 **6-12 个月**。
2. **语义调度前沿对齐**：学术 2025 的 ReuseProb 语义淘汰与 TDS DomainPredictor 同向；TDS 更进一步给出**可解释的中华文化优先级**（命宫/生克/比劫），这是可宣传的差异化。
3. **玄学 × 系统软件跨界空白**：玄学软件不懂系统调度，系统调度不懂玄学。紫梅把两者缝合，天然稀缺。
4. **进化引擎**：LM Studio 等无"自进化档案/回退"概念；TDS 双线引擎（总体/IP）+ 风险分级 + 档案回退是工程领先点。

## 4. 领先窗口判断

- 组合稀缺度：无竞品同时具备「可解释语义调度 + 淘汰序推演 + 预取预测 + 进化档案」→ **整体领先窗口 6-12 个月**。
- 单点窗口：调度可视化（P0-2）窗口约 6 个月；进化档案（P0-4）窗口约 12 个月（LM Studio 等短期不会做可回退自进化）。
- 风险：SGLang/vLLM 等若把调度可视化并入官方 UI，窗口会缩短；对策是把"命理可解释性"做成不可复制的护城河，并用实验分支接口保证增量不破稳定主线。

## 5. 落地路径

- 内核不动：所有前瞻增量走 zimei_app（独立软件）与 tds.testing（实验分支），tds-core 不引入新硬依赖。
- GUI 增量按 P0 → P1 → P2 顺序排期，每项以"可视化 + 解释 + 可回退"三要素验收。
- 与 LMSL 启动器路线协同：策略包签名分发（P2-10）复用 LMSL 自有签名体系。
